## Findings

- Vendure 3.7.3's `ExceptionLoggerFilter` rewrites REST `HttpException` bodies as `{ statusCode, message, timestamp, path }`. The command controller sets 409/503 through an injected Express response and returns the medusapos body directly, preserving `{ code: 'in_progress', id }` and `{ code: 'transient', id, message }` without `results`.
- Vendure's channel service only updates `defaultTaxZone` for a truthy `defaultTaxZoneId`; passing null does not clear an assigned zone. Proof 10 uses the real configuration hole of an assigned default tax zone with all its rates disabled. The pre-claim check requires an enabled rate without a customer-group restriction and returns `store_configuration` without creating an order or ledger row.
- The ledger claim is Postgres-only: it uses `INSERT ... ON CONFLICT` and `SET LOCAL lock_timeout = '5s'`, resetting the timeout immediately after the claim.
- Vendure 3.7.3's `orderConfirmationHandler` listens to `OrderStateTransitionEvent` (to `PaymentSettled`, with a customer), not `OrderPlacedEvent`, so the POS filter is added to that handler. With the `testing` transport the `EmailPlugin` sends in-process and never enqueues a `send-email` job, so proof 3 waits for the handler rather than for a queue.
- `PaymentService.createPayment` runs the method's eligibility checker, so the recipe's own payments pass `tally-pos`'s checker only because the order carries `tallyClientOrderId`. The REST route's `RequestContext.apiType` is `custom`, which the handler guard relies on. A Shop API order with a forged `tallyClientOrderId` passes the checker and gets a `Declined` payment (`PaymentDeclinedError`).
- The shortage cut is not silent in 3.7.3: `addItemToOrder` saves the line at the saleable quantity and returns `InsufficientStockError`, so without the top-up the recipe would reject the sale; `addItemsToOrder` returns the cut order beside `errorResults`. The transition to `ArrangingPayment` checks saleable stock again, so the top-up stays until after fulfilment. The top-up and take-back are `ADJUSTMENT` movements at the default stock location, and Vendure lets on-hand stock go negative (-1 after selling 3 of 2).
